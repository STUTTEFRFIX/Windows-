 # 性能监测 · 使用说明

一个深色小窗，每秒刷新显示这台电脑的 CPU、内存、GPU、磁盘、网络负载。

---

## 一、怎么打开

双击程序目录里的 **`启动性能监测.cmd`** 即可。

也可以直接双击桌面快捷方式（如果有），或者在 PowerShell 里执行：

```
"C:\Program Files\dotnet\dotnet.exe" "D:\DS\perf-monitor\bin\性能监测.dll"
```

### 为什么是 .cmd 而不是 .exe

这台电脑上**没有安装 .NET SDK，也没有 Windows 的 exe 宿主模板**，所以无法生成一个独立的 `性能监测.exe`。
程序本身是编译好的 .NET 程序（`性能监测.dll`，约 31 KB），由系统里**已经装好的 .NET 运行时**来启动。
所以需要那个 `.cmd` 中转一下——**双击的体验和 exe 完全一样，不会弹出黑框**。

如果以后装了 .NET SDK，我可以重新编译成真正的独立 `性能监测.exe`，直接双击。

## 三、指标来自哪里

| 指标 | 数据来源 | 说明 |
|---|---|---|
| CPU 总占用 / 每核心 | `NtQuerySystemInformation` | **与任务管理器同口径**，实测与性能计数器一致（27.5% vs 27.9%） |
| 内存已用 / 总量 | `GlobalMemoryStatusEx` | 物理内存 |
| GPU 负载 / 显存 / 温度 / 功耗 / 风扇 / 频率 | `nvidia-smi` | 一次调用取回全部；NVIDIA 驱动自带 |
| 磁盘读写 | 性能计数器 `PhysicalDisk` | 读不到时显示 `--` |
| 网络上下行 | `NetworkInterface` 字节数差分 | 只统计状态为 Up 的网卡 |

**显示 `--` 的意思**：该项这次没取到（例如驱动正在更新、该计数器不可用）。程序不会因此崩溃，下一轮会自动重试。

## 四、出问题了怎么办

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 双击 `.cmd` 没反应 | .NET 运行时缺失 | 装一次 .NET 8 或 10 桌面运行时（微软官网免费） |
| GPU 一栏全是 `--` | 不是 NVIDIA 显卡，或驱动在更新 | 等两分钟重启程序；A 卡/核显本来就取不到这些项 |
| 风扇显示 `-- %` | 该卡不向驱动上报风扇转速 | 正常现象，Max-Q 笔记本常见 |
| 磁盘/网络显示 `--` | 对应计数器或网卡不可用 | 正常降级，其余指标不受影响 |
| 窗口跑到屏幕外 | 显示器配置变了 | 关掉重开，程序启动时会回到屏幕中央 |
| 内存数字比预期大 | 见下节 | 属于 .NET 运行时基线，不是泄漏 |

## 五、关于内存占用（重要，请如实了解）

**实测：工作集 61.5 MB，私有内存 27.8 MB。没有达到最初设想的 10 MB。**

原因：程序跑在 **.NET 运行时的宿主进程**里，而 .NET 桌面程序的内存基线本身就在 **25~35 MB**
（CLR 运行时 + JIT 编译 + 垃圾回收器 + WinForms + GDI+ 图形库）。这部分**不是这个程序的代码造成的**，
是平台的地板。程序自己的托管堆只有约 5 MB。

窗口底栏显示的 `本程序内存` 就是真实工作集，您可以随时自己核对，不用信我。

要真正压到 10 MB 以内，只有改用 **C++ / Rust + 原生 Win32 API** 重写——但**这台电脑上没有 C++ 编译器，
而且网络被封装不了**，所以目前做不到。等有了编译器我可以另做一版。

## 六、源码与重新编译

```
D:\DS\perf-monitor\
  src\Collector.cs    采集层（原生 API + nvidia-smi）
  src\Ui.cs           界面层（GDI+ 自绘，双缓冲）
  src\MainForm.cs     程序入口 + 无界面自检模式
  build.ps1           一键编译（用 PowerShell 7 自带的 Roslyn，不需要 .NET SDK）
  capture.ps1         抓取窗口截图
  bin\                产物（性能监测.dll + 启动器）
```

重新编译：右键 `build.ps1` → 用 PowerShell 运行，或在终端执行

```
pwsh -NoProfile -File D:\DS\perf-monitor\build.ps1
```

**注意**：编译前必须关掉正在运行的程序，否则 `性能监测.dll` 被占用会编译失败。

自检模式（不开窗口，把采集结果写到文件，用于排查数据问题）：

```
"C:\Program Files\dotnet\dotnet.exe" "D:\DS\perf-monitor\bin\性能监测.dll" --selftest D:\out.txt
```

## 七、界面设计基准

界面不是随手画的，有生成器和自检脚本（在 `D:\DS\docs\`）：

| 文件 | 作用 |
|---|---|
| `build_mockup.py` | 生成 1:1 效果图（PNG + SVG 同源） |
| `audit_overlap.py` | 逐元素矩形求交 + 横向/纵向越界 + **卡片是否真有卡面** 的自动检查 |
| `captain_recheck.py` | WCAG 对比度 / 数字墨迹对齐 / 曲线缩放后波动 |
| `性能监测软件-需求文档.md` | 完整需求、配色板、排版规则 |
| `界面草图.png` | 效果图 |

**程序里的版式常量与 `build_mockup.py` 一一对应**（卡高 CPU=205 / 内存=199 / GPU=223 / 磁盘=138，
窗口 420×927）。改版式时两边必须同步，否则会像开发过程中那样出现"窗口高度和实际绘制脱节"。
